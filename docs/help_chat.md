# ナビの「使い方」（よくある質問と AI への質問）

ナビ画面（`/navi/`）の上にある「？」ボタンから開く。中身は3つ。

1. **よくある質問**：`programs/html/navi/faq.json` の質問と答えを並べたもの。AI を使わないので、設定なしで動く
2. **AI に質問する**：上にない質問を Gemini に答えさせる。`GEMINI_API_KEY` を設定するまでは「今は使えません」と出る
3. **オペレーター（人）に相談する**：AI に質問したあと、受け付けているオペレーターがいるときだけ
   「オペレーター（人）につなぐ」が出る。オペレーターは集計システムの管理画面（`/admin` の「相談窓口」）で返事をする

### 利用者がオペレーターにつながるまで

1. オペレーターが管理画面の「相談窓口」で「受け付ける」を押しておく
2. 利用者がナビの「？」を押し、「AIに質問する」の欄に何か送る（AI が使えないときも、送れば出る）
3. AI の答えの下に「オペレーター（人）につなぐ」が出るので押す（受け付けているオペレーターがいないときは出ない）
4. 相談したいことを書いて送ると、管理画面の一覧に「返事待ち」で出る

## しくみ

```
ブラウザ（navi/script/help.js）
  └─ POST /api/help-chat  … 同じ iku-navi.net の Pages Functions（functions/api/help-chat.js）
        ├─ /navi/faq.json を読み、「使い方の説明」として Gemini に渡す
        └─ Gemini API（generateContent）
```

- API キーはサーバー側（Pages の環境変数）にだけ置き、ブラウザには出さない
- Gemini には「faq.json に書かれていることだけで答える」「場所を推測で答えず、目的地に入れて検索するよう案内する」
  「使い方と関係ない質問には答えない」と指示している（`functions/api/help-chat.js` の `SYSTEM_PROMPT`）
- **答えの元は faq.json**。AI の答えを直したいときは、まず faq.json の説明を足す・直す
- 受け付けるのは、同じサイト（`Origin` が同じ）からの POST だけ。1回の質問は 400 文字まで、やりとりは直近 10 件まで送る
- 会話はサーバーに保存しない（ページを閉じると消える）

## 使えるようにする手順

### 1. Gemini の API キーを作る（Google AI Studio）

1. https://aistudio.google.com/apikey を開き、プロジェクトの Google アカウントでログインする
2. 「API キーを作成」を押し、キー（`AIza…`）を控える。**キーはリポジトリやチャットに貼らない**

### 2. Cloudflare Pages に設定する

1. https://dash.cloudflare.com/ → 「Workers & Pages」→ IKU NAVI 本体の Pages プロジェクト
2. 「設定」→「変数とシークレット」→ **Production** に追加する
   | 名前 | 種類 | 値 |
   |---|---|---|
   | `GEMINI_API_KEY` | シークレット（暗号化） | 手順1のキー |
   | `GEMINI_MODEL` | テキスト（省略可） | 省略すると `gemini-3.5-flash-lite` |
3. Preview でも試したいときは、Preview にも同じものを入れる
4. 設定は次のデプロイから効く。「デプロイ」タブで最新のデプロイを「再試行」すればすぐ効く

### 3. 送りすぎを止める（Cloudflare のレート制限ルール）

同じ IP から短い時間に大量に送られたら、しばらく止めるルールを作る。
無料プランではこのルールを **1 つしか作れない** ので、集計システムの記録（`/api/track/`）・AI への質問・
オペレーターへの相談を、**1 つのルールにまとめて** 入れる（集計システムの README の手順9 は、このルールで済む）。

1. https://dash.cloudflare.com/ にログインし、**`iku-navi.net`** のドメインを開く
2. 左のメニューの **「セキュリティ」→「WAF」→「レート制限ルール」タブ** を開く
   （新しい画面では **「セキュリティ」→「セキュリティルール」** の中にある）
   - すでにルールが 1 つある（手順9で作った）なら、そのルールの「編集」を押す
   - 無ければ **「ルールを作成」** を押し、ルール名に `iku-navi api` と入れる
3. 「受信リクエストが一致する場合」の右にある **「式を編集」**（Edit expression）を押す。
   入力欄が文字の欄に変わるので、中身を全部消して、次をそのまま貼る:

   ```
   (http.host eq "event-guide-counter.iku-navi.net" and (starts_with(http.request.uri.path, "/api/track/") or http.request.uri.path in {"/api/support/start" "/api/support/send"}))
   or (http.host eq "iku-navi.net" and http.request.uri.path eq "/api/help-chat")
   ```

4. 残りの欄は次のとおりにする:

   | 項目 | 入れる値 |
   |---|---|
   | 同じ特性を持つ場合 | IP |
   | レートが次を超えた場合 | リクエスト数 `20`、期間 `10 秒` |
   | アクションを実行 | ブロック、期間 `10 秒` |

5. **「デプロイ」**（編集した場合は「保存」）を押す

- オペレーターへの相談の **数秒ごとの確認（`/api/support/poll`）は入れない**。鳳祭の当日は学内 Wi-Fi などで
  多くの人が同じ IP になるので、確認まで数えると、普通に相談している人が止められてしまうため
- 式が長くて貼れない・エラーになるときは、式をそのまま Claude に見せて相談する

### 4. 本番で確かめる

1. スマートフォンで https://iku-navi.net/navi/ を開き、「？」を押す
2. よくある質問が開けること、「AI に質問する」に「ゼミ44Aへの行き方は？」と送って、目的地に入れて検索するよう答えが返ること
3. 「今日の天気は？」など関係ない質問に、答えないこと

## オペレーターに相談する（相談窓口）

### しくみ

```
ナビ画面（help.js） ──数秒ごとに確認── 集計システム /api/support/*（ログイン不要、iku-navi.net からだけ）
                                          │ D1（support_conversations・support_messages・support_operators）
管理画面（/admin の相談窓口） ─4秒ごとに確認─ 集計システム /api/admin/support/*（管理者だけ）
```

- 置き場所は集計システム（`programs/event_guide_counter`）。ログイン・DB・管理画面をそのまま使う
- オペレーターになれるのは、管理画面に入れる人（`ADMIN_EMAILS`）と同じ
- 利用者はログインしない。相談を始めると、その相談だけに使える合言葉（トークン）が利用者の端末に保存され、
  DB にはそのハッシュだけを残す。ページを開き直しても、相談の途中から続けられる
- 届くまでにかかる時間は、利用者の画面を開いている間は最大 3 秒、オペレーターは最大 4 秒
- 1 通は 500 文字まで、1 つの相談で利用者が送れるのは 40 通まで、同時に続けられる相談は 50 件まで
- 終わってから 14 日を過ぎた相談は、オペレーターが「受け付ける」を押したときに消える

### オペレーターのやり方

1. パソコンで `https://event-guide-counter.iku-navi.net/admin` を開き、Google でログインする
2. 一番上の「相談窓口」で **「受け付ける」** を押す。これで利用者の画面に「オペレーター（人）につなぐ」が出るようになる
3. 相談が来ると音が鳴り、タブの名前に未読の数が出る。左の一覧から相談を選び、下の欄に返事を書いて送る
   （Ctrl+Enter / ⌘+Enter でも送れる）。つなぐ前に AI とやりとりしていれば、「つなぐ前の AI とのやりとり」で読める
4. 解決したら「相談を終える」。利用者の画面にも終わりのお知らせが出る
5. 抜けるときは **「受け付けをやめる」**。別のタブにしていても受け付けは続き、相談が来ると音が鳴る。
   画面を閉じる・パソコンがスリープすると、1 分半ほどで自動的に受け付けが止まる
   （その間に始まった相談は一覧に残るので、ほかのオペレーターか、戻ってきたときに返事をする）

- 管理画面を開いている間は 4 秒ごとに確認するので、閲覧記録（画面の下の表）がその分増える
- 利用者の名前・連絡先などの個人情報は聞かない

### 使えるようにする手順

集計システムの本番の設定（`programs/event_guide_counter/README.md` の手順4〜10）が済んでいれば、追加でやることは次の 1 つだけ。
相談窓口の表（`migrations/0002_support.sql`）を本番の D1 に作る:

```bash
cd programs/event_guide_counter
npm run db:migrate:remote
npm run db:migrate:preview
```

（手順4をまだやっていなければ、手順4のときに一緒に作られる）

### D1・Functions の無料枠

- Functions は 1 日 10 万回まで。オペレーター 1 人が 8 時間開いていると約 7,200 回、
  利用者 1 人が 10 分相談すると約 200 回使う
- D1 の書き込みは 1 日 10 万回まで。オペレーターの画面は 4 秒ごとに 2 回書き込む（受付の確認・閲覧記録）ので、
  1 人 8 時間で約 1 万 4,000 回。オペレーターを同時に 4 人以上にするときは、ダッシュボードで使った量を見る

## 費用とデータの扱い

- **無料枠**：料金はかからないが、1 分・1 日あたりの回数に上限がある。超えると「いま質問が集中しています」と出る。
  また、**無料枠では、送った質問が Google の製品改善に使われる**（画面に「個人情報は書かないでください」と出している）
- **有料枠**（AI Studio で請求先を設定）：質問は製品改善に使われない。料金は使った分だけ
  （2026-10 時点の Gemini 3.5 Flash-Lite は、入力 100 万トークンあたり $0.30、出力 $2.50。
  1 回の質問は、説明を含めて入力 2,000〜3,000 トークンほど）。使いすぎに気づけるよう、Google Cloud で予算のアラートを設定しておく
- 料金とモデルは変わるので、https://ai.google.dev/gemini-api/docs/pricing と https://ai.google.dev/gemini-api/docs/models で確かめる

## 止めたいとき

Pages の `GEMINI_API_KEY` を消して再デプロイすると、AI への質問だけが止まり「今は使えません」と出る（よくある質問はそのまま使える）。
キーが漏れたときは、AI Studio でそのキーを削除してから作り直す。

## よくある質問を直すとき

`programs/html/navi/faq.json` を直してデプロイするだけ（画面と AI の両方に効く）。
画面のボタンや欄の名前を変えたときは、faq.json の書き方も合わせる（AI もこの名前で案内する）。
