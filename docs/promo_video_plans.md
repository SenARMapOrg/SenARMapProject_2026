# IKU NAVI 紹介動画 構成案

2026-11-12 作成、2026-11-19 更新（外した機能を消し、数字を今のデータに合わせた）。プロジェクト全体（IKU NAVI＝製品と、生亀プロジェクトの1年間）を紹介する動画の構成案。

- **A. 3分フル尺版**（横 16:9 を想定）… 10案
- **B. 1分ショート×3本で1セット**（縦 9:16 を想定）… 11案
  - 1本ずつ単体でも成立し、3本続けて見ると約3分の「一本」になるように組んである
  - B-9（1分クッキング）と B-11（作業風景、30秒・1分）は1本で完結する

## A. 3分フル尺版（10案）

### A-1. 王道プレゼン型「迷う → 解決 → 仕組み → これから」

**向いている場**: 最終発表・学内の紹介・初めて見る人全般。迷ったらこれ。

| 時間 | 内容 |
|---|---|
| 0:00–0:15 | 生田キャンパスの空撮風カット（坂・建物の多さ）。テロップ「この中から、次の教室を探せますか？」 |
| 0:15–0:40 | 課題：号館が多い・階がずれている（地下や0階）・初めての人はまず迷う。新入生／来場者が迷う再現カット |
| 0:40–1:30 | 解決：IKU NAVI のデモ。教室名入力 → 屋外マップ → 建物に入るとフロアマップ → 経路写真と矢印 → 到着 |
| 1:30–2:00 | 機能の早回し：屋外AR／音声案内／階段を使わない経路／最寄りのトイレ・食堂／3Dマップ |
| 2:00–2:35 | 仕組み：写真約1,300枚の撮影、グラフと最短経路、950回超のコミット、鳳祭での運用 |
| 2:35–3:00 | これから＋締め：「使える製品として送り出す」。URL（iku-navi.net）とQRを大きく |

### A-6. ワンカット風「1本の経路を3分で歩く」

**向いている場**: 製品の体験そのものを見せたいとき。編集の手間を撮影側に寄せたいとき。

- 正門（またはバス停）から、遠い号館の上の階の教室まで、実際に歩く1本の経路を、つながって見えるように撮る（実際は数カットをつなぐ）
- 画面の右下にスマホ画面をワイプで常時表示。ナレーションは最小限、音声案内の読み上げを主役にする
- 区間が切り替わるたびに小さなテロップ（屋外AR → 入口 → 2階 → エレベーター → 到着）
- 2:40 で到着、ドアを開ける。所要時間と「迷った回数：0」→ URL

※ 経路は、写真・フロアマップが揃っている区間を事前に IKU NAVI ツールで確認してから選ぶ。

| 2:45–3:00 | 全レイヤーを重ねて、また普通の画面に戻る →「これを全部、学生でつくりました」 |

### A-8. インタビュー型「作った人と使った人」

**向いている場**: 人の顔が見える紹介にしたいとき。ドキュメンタリー寄り。

- メンバー（データ・撮影・フロント・インフラなど役割ごと）と、鳳祭や学内で使った人の声を交互につなぐ
- 質問の例：「なぜ作ったのか」「一番大変だったこと」「使ってみてどうだった？」「残っている課題は？」
- 質問の合間に、その答えに対応する画面・現場カットを挟む（「写真撮影が大変」→ 雨の中で撮っている写真）
- 最後に全員に同じ質問「この先どうしたい？」→ それぞれの答え → URL

### A-9. ショートドラマ型「遅刻まであと5分」

**向いている場**: SNSで広く見てもらいたいとき。演技できるメンバーがいるとき。

| 時間 | 内容 |
|---|---|
| 0:00–0:20 | 寝坊して駅を走る主人公。教室番号だけ覚えている。画面端に残り時間のカウントダウン |
| 0:20–0:50 | キャンパスに着くが、その号館が分からない。友達に電話しても「たぶんあっち」 |
| 0:50–1:50 | IKU NAVI を思い出す。屋外AR → 建物 → 目の前でエレベーターが閉まる → 「階段」の経路に切り替えて駆け上がる |
| 1:50–2:30 | 教室の前に着く。…が、そこは別の号館の同じ番号の部屋（あるあるのオチ）→ もう一度検索して正しい教室へ |
| 2:30–3:00 | 着席と同時にチャイム。エンドロール風に「この経路はこうやって作られました」の早送り → URL |

### A-10. 数字で見せるモーショングラフィックス型「IKU NAVI in Numbers」

**向いている場**: 実写の撮影が難しいとき。スライドの代わりに流したいとき。

- 実写を減らし、数字のカウントアップとキャンパス3Dマップの回転で見せる
- 並べる数字の例：号館の数／フロアマップの枚数／ノード・エッジの数／経路写真の枚数／コミット数／ブログ記事数／鳳祭の案内人数／navi1〜9 のUI案の数
- 数字ごとに 15〜20秒、「その数字の意味」を1文で添える（例：「写真約1,300枚 = 曲がり角ごとに1枚」）
- 最後の数字を「あなたが迷う回数：0」にして URL

※ 数字は撮影直前にデータから数え直す（`data/` の CSV、`git rev-list --count HEAD`、集計システムの管理画面）。

## B. 1分ショート×3本セット（10案）

共通の作り方:

- **最初の1〜2秒で止める**（文字だけのフック、問いかけ、意外な画）。ロゴやタイトルから始めない
- **テロップは大きく・画面中央寄り**（下はUIで隠れるので、下から15%は避ける）
- **1本の最後に次の回への引き**（「Part2 で〇〇します」）を入れ、3本目の最後だけ URL・QR で締める
- 3本を続けて流すと3分の1本になるよう、各回の冒頭5秒で「前回のあらすじ」を入れない（通しで見たときにくどくなる）。代わりに固定タイトル（#1/#2/#3）で区別する
- **B-9（1分クッキング）と B-11（作業風景）は例外**で、1本で完結する

### B-1. 大学生あるある寸劇「生田キャンパスあるある」

**参考にする型**: 学生・社会人のあるあるショートドラマ（1シチュエーション＋オチ）

| 回 | 内容 |
|---|---|
| #1「教室が見つからない」 | 新入生が同じ廊下を3往復 → 先輩がスマホを見せる → 一直線で到着。オチ「先輩も去年3往復してた」 |
| #2「トイレどこ問題」 | 授業中に抜け出して迷う → 「最寄りのトイレ」で一発。オチ「授業に戻る経路も出せる」 |
| #3「足をケガした日」 | 松葉杖の友達と階段の前で立ち尽くす → 「階段・エスカレーターを使わない」→ エレベーター経由で到着。最後に「作ったのはこの人たちです」でメンバー登場 → URL |

### B-2. POV「はじめて生田キャンパスに来た日」

**参考にする型**: 一人称視点のPOVショート（画面の向こうの「あなた」に話しかける）

| 回 | 内容 |
|---|---|
| #1「POV: 入学初日、教室が分からない」 | 主観カメラで坂を上る。スマホを取り出し屋外ARの矢印が浮かぶところで終わる |
| #2「POV: 建物に入った瞬間に地図が変わる」 | 入口で屋内のフロアマップに切り替わる気持ちよさを見せる。経路写真と目の前の景色が一致するカット |
| #3「POV: 迷わず着いた」 | 着席。隣の席の人が迷って遅れてくる → 画面を見せてあげる → URL |

### B-3. 検証・対決「IKU NAVI でキャンパスを攻略できるか」

**参考にする型**: 「〇〇してみた」検証系、タイムアタック系

| 回 | 内容 |
|---|---|
| #1「前編：ルール」 | キャンパスで一番遠そうな教室を、初めて来た人が地図なしで目指す → 迷う様子（タイム表示）で引き |
| #2「中編：IKU NAVI 解禁」 | 同じ人が別の教室を IKU NAVI で。屋外AR・写真ナビ・音声案内を順に使う |
| #3「結果」 | タイム比較と本人の感想。「なぜ屋内で差が出るのか」を15秒で → URL |

### B-4. AIボイス解説（ずんだもん等の合成音声キャラ）

**参考にする型**: 合成音声キャラ2人の掛け合い解説ショート

| #2「どうやって道を探してるのだ？」 | ノードとエッジ、最短経路、写真を曲がり角ごとに撮っていることを図解 |

※ 使う音声キャラの利用規約（クレジット表記・商用可否）を必ず確認し、動画内に表記する。

### B-8. ルーティン型「授業がある日のルーティン」

### B-9. 料理番組型「1分クッキング　キャンパスナビ」

> **この案だけは3本セットではなく、1分の1本で完結する。** 材料 → 調理 → 完成・試食までを1本に詰め込む。番組名どおり、きっちり1分で終わること自体がネタになる。

**参考にする型**: テレビの短い料理番組のパロディ。先生とアシスタントの2人がキッチンに立ち、「今日は〇〇を作ります」→ 材料 → 手順 →「こちらが出来上がったものです」と進める

**この案のねらい**: 技術の話（グラフ・最短経路・サーバー）を、料理の言葉に置き換えて技術を知らない人にも見せる。数字はすべて実データ（2026-11-14 時点。撮影前に数え直す）なので、ふざけた見た目のまま「ちゃんと作っている」ことが伝わる。

**配役と見た目**

- **先生**: エプロン姿のメンバー（開発の中心の人）。落ち着いた口調で、専門用語をさらっと言う
- **アシスタント**: 別のメンバー。視聴者の代わりに聞き、驚く役
- **セット**: 机に白い布をかけてキッチン台に見立て、正面から撮る。手元のアップは真上から別に撮って差し込む。台の上にノートPC・フロアマップ・印刷した写真・スマホ
- **お決まり**:
  - 冒頭の挨拶「1分クッキングの時間です」
  - 画面の角に残り時間（1:00 からのカウントダウン）を最後まで出す
  - 時間が足りない工程は「こちらに 〇〇したものを用意しておきました」で飛ばす
- **注意**: 実在の料理番組のテーマ曲・ロゴ・番組名・提供の表示は使わない。BGM は著作権フリーの軽快な曲にし、「料理番組っぽさ」は挨拶・セット・カウントダウンで出す

- テロップを読み切れる速さではないので、材料表は「一時停止したくなる」密度でよい。保存・繰り返し再生を狙う
- 写真1,317枚を全部印刷する必要はない。ボウルには数十枚を盛り、テロップで枚数を出す
- 数字は撮影の直前にデータから数え直す（`data/` の CSV の行数。経路写真は `edge_image.csv` の写真の種類の数）

### B-11. 作業風景「IKU NAVI ができるまで」

> **この案も B-9 と同じく、1本で完結する。** 1分版を基本にし、★の付いたカットだけをつなぐと30秒版になる。

**参考にする型**: 学生・エンジニアの作業風景ショート（「作業用BGM」系）。ナレーションなし、落ち着いたBGM（lo-fi など）、画面の隅に小さなテロップだけ。カットはBGMの拍に合わせて切り替える

**この案のねらい**: 完成した画面ではなく「作っている手元」を見せて、ナビの裏に地道な作業があることを伝える。最後に完成品が動くことで、作業の意味が一気に分かる構成にする。しゃべらないので、撮影の負担が小さく、出演が苦手なメンバーでも参加できる

**見た目のルール**

- 顔は映さず、**手元・画面・背中・足元**だけで撮る（同意の手間が減り、作業風景らしくなる）
- テロップは小さく、画面の左上に「作業内容」と「日付」だけ（例：`2026.06 経路写真の撮影`）。日付はブログ・コミットの実際の時期に合わせる
- 色味をそろえる（全カット少し暖色に寄せる）と、別々の日に撮った素材でも1本に見える
- 過去の作業は撮り直しでよい。そのときの画面（コミット履歴・ブログ・古い3Dビューア）を映して「当時」に見せる

## C. 撮影・制作の注意

- **人の写り込み**: キャンパス内の撮影は大学の許可を確認する。映る人には同意を取り、取れない人はぼかす
- **大学名・ロゴ**: 専修大学の名前・校章・ロゴを動画に出す場合の扱い（許可が必要か）を事前に確認する
- **BGM・効果音・音声キャラ**: 著作権フリー・利用規約を確認し、必要なクレジットを入れる。SNS のアプリ内楽曲は、そのSNSに上げる版にだけ使う
- **画面に出す情報**: API キー・管理画面（案内人数の集計など）・個人情報が録画に映らないようにする。管理画面を見せるならダミーデータで
- **実際の動きと違うことを見せない**: 今のデータでは5号館・7号館にエレベーターが無く、「階段・エスカレーターを使わない」では5号館の2・3階と7号館の地下1階・2・3階へは案内できない。この機能を見せる経路は、行ける建物で撮る
- **撮る前に経路を確かめる**: 撮影に使う経路は、写真・フロアマップが揃っているかを事前に IKU NAVI ツールで確認しておく
- **縦型と横型**: ショートは 9:16、フル尺は 16:9。撮影は横で広めに撮っておき、縦は切り出す方が両方に使い回しやすい（スマホ画面の録画だけは縦で撮る）
